# Decisions

- Deterministic collection happens before AI synthesis.
- `OBSERVED`, `INTERPRETATION`, and `WATCH` remain separate.
- Cuttingboard is optional, read-only context and never writable authority.
- PRE-MARKET is the first shipping cadence.
- Local and simple comes before services or frameworks.
- Signal over plumbing: the brief carries conclusions and useful tables; collapsed ledgers carry proof.
- A commissioning run names the market phase it actually collected in (resolved from the exchange clock), never a hardcoded checkpoint.
- Same-day post-close runs may use daily history through the prior completed session while the provider has not published today's bar; that lag is visible in coverage, never fills TODAY, and never applies beyond that day.
- Only LIVE runs publish; fictional replay output never reaches the public brief.
- The synthesis contract asks for one short headline claim, one global coverage caveat, and no table restatement; the validator enforces the headline bound and fail-closed grounding unchanged.
- The model receives the bounded synthesis projection (one copy of each admitted fact, legend, leadership IDs, attention, compact sources, coverage, schema); the full normalized record stays local and `--full-packet` reproduces the original payload for diagnostics.
- Deterministic code owns every persistent continuity identity (watch, relationship, comparison, snapshot ref); the analyst proposes new items and assessments and never names or renames a carried record.
- Saved artifacts separate deterministic observed/comparable change (`observed`) from model-authored assessment (`assessment`, class INTERPRETATION); the point-in-time factual record stays usable without the interpretation.
- Premarket admits only the previous exchange session's accepted close handoff; intraday editions admit this session's premarket anchor and latest accepted edition. Anything else is an explicit cold start.
- A checkpoint that was accepted but never published stays the analytical anchor, and the reader is told so (2026-10-12, after the OPEN_1M push was refused). Each page carries `data-evidence-cutoff` on `<html>`. A run compares that attribute, on the page its checkout holds, with its same-session anchors. An anchor later than that page was accepted and not published, so What changed reads "vs premarket and the unpublished 6:32 AM PT refresh". The wording is frozen with the interpretation, so every refresh under it says the same. Anchors, comparisons, continuity and the analyst's context are unchanged. A page without the attribute, or no page, decides nothing.
- A post-close run may admit labeled PROVISIONAL session-ending prints (final fifteen minutes before the close, within ninety minutes after it) so a cron-delayed close can still hand off; the handoff and its closing character are marked provisional. Without any session observation the run records EARLIER_HISTORY_ONLY and does not advance the close handoff; the next morning says close continuity is unavailable.
- GitHub Actions artifacts are short-horizon operational continuity (thirty days), not historical storage; artifact contracts are versioned and hashed so a permitted archive can adopt them later.
- Restore takes the newest unexpired continuity artifact of a main-branch `schedule.yml` run that concluded `success` or `failure`. Its upload runs only when every earlier step, the pipeline among them, succeeded, and precedes the push and the Pages deployment, so the artifact proves acceptance and a push or Pages failure no longer rolls accepted state back (R1). A rejected synthesis uploads nothing; a cancelled or unfinished run is not eligible. Only this repository's own runs are eligible (S1): the run's `head_repository` must be the `repository` that owns it, by their integer ids on the run (schema-required, though a deleted fork's head comes back null), because a fork's pull_request run executes its own edit of the workflow and can upload a same-named artifact from a branch it named main; missing, null or malformed origin is not eligible. R2's attempt lookup decides origin with the same check on its run details, never the listing's optional ids. Only the absence of an eligible bundle is a cold start; a restore that cannot finish (the GitHub API, a run lookup, the download, a timeout, installing the bundle) fails its step and stops the run before collection, because that run's cold bundle would otherwise replace accepted state for every later run. The run archive is diagnostic: it comes after the continuity upload and publication and runs `always()`, so its own failure can gate neither.
- The publish step pushes only its own commit, never forced (2026-10-12, after the OPEN_1M push GitHub refused with "fatal error in commit_refs", main unmoved). It makes up to three attempts, 10 s then 20 s apart, while main is still the commit the run checked out. If main has moved, it stops at once and the newer main stands. If main is already its commit, it is published. Any failure lands after the continuity upload, so the run stays restorable. A three-minute step timeout makes a hung push a failure, not a cancel.
- One paid synthesis per checkpoint per exchange session, across runners, accepted or not (R2). The authority is that a provider request was attempted, never that its analysis was accepted: a production synthesis writes `runs/attempts/<session>-<checkpoint>.json` before the request is sent (no record, no request), the workflow uploads it last and `always()` as `market-brief-attempt-<session>-<checkpoint>`, and `scheduled()` never pays for a checkpoint with a local record or that artifact from a `schedule.yml` run on `main`; a listing it cannot read is no request and a failed run. The concurrency group finishes that upload before another run starts. Attempt records are accounting, never continuity; they are keyed by the run's own calendar date (as the page and bundle are) and count only from this repository's own runs, never a fork's. An attempt that bills nothing after the record is written (authentication, rate limit, 5xx, timeout) still consumes the checkpoint. Experiments and commissioning are never recorded; a manual production dispatch is recorded and, since W43 (S2a), gated too: when this checkpoint's paid attempt is already recorded it is refused before any request unless dispatched with `repay`, the owner's explicit second payment; a manual run outside the due window is allowed and recorded as `outside_window`.
- A comparison id cited as evidence is rewritten to the two observations it compares before validation, and nowhere else (owner ruling OD-1, 2026-10-17, after the 2026-10-16 OPEN_30M rejection of `cmp-latest-AAPL-intraday` in `watch_updates[1]`). A comparison is defined as its `current_ref` and `prior_ref`, so the rewrite adds nothing: it applies only in records that admit prior refs (watch updates, carried relationships, changes), only for comparisons whose two operands were both supplied, by table lookup. Every validator rule then runs on the result; an alias anywhere else, or one without supplied operands, is still rejected. The rewrite is printed, recorded in `repairs` (each rewritten list, its aliases, original and result) with the response as returned kept as `narrative.returned.json`, and listed in Technical details; the archived diagnostic of any rejection is the response as returned, and editorial overshoot is measured on it. A malformed or repeated citation list is never rewritten. `analyst.repairs` in `config/editions.json` enables it; an empty list turns it off. No second model request is made: a paid repair turn was declined. Every reference rejection now names its record path and the reference, and a refresh refused for stale prints says how many were too old and when the newest was stamped.
- A rejected opening analysis still publishes its checkpoint (owner ruling OD-1, 2026-10-17). When a production synthesis checkpoint's generation was attempted and not accepted (a rejected response, a failure after the request was sent, or a context over its budget) and the session already has an accepted interpretation from an earlier checkpoint, the run renders the deterministic refresh of the same collection under that interpretation, publishes it and uploads continuity as a refresh does: the observed record advances, the frozen interpretation does not. The page says the analysis was not accepted and which analysis stands; metadata records `validation: DEGRADED`, the error, the paid call and `degraded_from`. It is never counted as a synthesis, makes no second request and recollects nothing; the checkpoint is complete, so a later wake skips it. A rejected PREMARKET has no interpretation to fall back to and still publishes nothing; a refusal or fault before any request, an experiment, a commissioning run and a re-run of a checkpoint whose own analysis already stands fail closed and never claim a rejection.
- Every scheduled checkpoint run writes a receipt (W43 S1a, `market-brief.receipt.v1`): GitHub's outcome for each stage (resolve, restore, pipeline, continuity upload, publish, main check, Pages deploy), the publish commit, the validation and error, the paid call's model, tokens and cost, and one outcome class (published, published_degraded, refused_stale_data, synthesis_rejected, push_failed, deploy_failed, not_deployed, restore_failed, skipped, ...). It is the last step, `always()` and never fatal, uploaded as `market-brief-receipt-<session>-<checkpoint>-<run id>` for ninety days. A receipt is accounting only: never restored, admitted or rendered. Deployment is GitHub's word; reader delivery stays `pending` until an observer outside the publication lane verifies the live page.
- The opening-structure update reads the full evidence record (owner ruling OD-2, 2026-10-17). OPEN_30M uses the `opening` profile: the rich catalog, bounds and 7,000-token ceiling, with the light profile's comparison projection (`comparisons: "changed"`, full records only for changed comparisons) and a 220–320 word target; still two analyst calls a day. Replayed offline on the four W42 OPEN_30M runs it reads 42,718–47,105 bytes against the unchanged 64,000 limit (rich as-is would read 57,948–61,089), and a synthetic CPI-day stress with the W43 rates and participation rows, more events and releases and three carried watches reads 53,389. The light profile stays defined and tested; no checkpoint uses it. The prompt's budget sentence no longer names 500 words.
- Treasury's official real (TIPS) par curve is collected beside the nominal one (W43 S3a): its own source (`treasury-real`, `data=daily_treasury_real_yield_curve`, the same allowlisted host), 5Y/10Y/30Y real levels and whole-bp changes under the nominal curve's rules (entries before today ET, the January fallback). Inflation compensation is derived only when the two curves share a date, in whole basis points from the published two-decimal yields, so nominal change = real change + inflation-compensation change holds exactly; a change is formed only against the same prior date. A real-curve failure never touches the nominal module. Reader words: "real yield" and "inflation compensation", never "expected inflation", with a fixed caveat that it carries inflation risk and liquidity premiums and that a real Treasury yield is not a company's or household's borrowing cost. The rates module shows the 10-year's split and a deterministic sentence (offsetting legs are said to offset, never given shares; an unchanged total whose parts moved says so); the other maturities are in the proof. A January fallback that fails is reported: the source reads Degraded and names the failed previous-year feed when the level stands without its change, or Unavailable with the same reason when no level stands (the nominal curve keeps its earlier behaviour). `"real_yields": false` in config/sources.json switches this one feed and its decomposition off without a revert; the source then reads Unavailable, "switched off in config/sources.json".
- A never-started Cloudflare wake never holds the scheduler's concurrency group past the next wake (L1, 2026-10-01, after run #203 on 2026-09-30). Before each dispatch the Worker normal-cancels the run holding `market-brief-pages` only when every piece of evidence is present: it is this repository's own `schedule.yml` `workflow_dispatch` on `main`, first attempt, named "Cloudflare wake-up" by the workflow's `run-name`; no job ever had a runner or a step; it is at least `TOLERANCE_MINUTES["synthesis"]` (twenty minutes) old, which it first is at the next wake, when a later checkpoint has superseded it: started then, it could no longer resolve the checkpoint associated with its original wake, and a fresh wake resolves exactly what it would (for OPEN_1M that is before its own 45-minute tolerance ends); and the run before it got a runner within those twenty minutes, so clearing never repeats in a row and a slow but live queue is never starved (its first wake still waiting at the next tick after a prompt run is cleared like a stalled one, a cost the owner accepted). The holder is the one unfinished run of the group with jobs, since a workflow-level group creates jobs only for its holder; anything unknown, malformed or ambiguous cancels nothing, and manual dispatches (only the Worker's exact inputs earn the wake name), `pages.yml`, other branches and started runs are only logged. It is safe because a run with no step sent no provider request, wrote no attempt record, uploaded no continuity and published nothing; the candidate is re-read just before the cancel, the cancel is a normal one (never force-cancel) and is verified, a runner that reached the run first is reported as such, and each outcome is logged by the Worker (the authoritative record) and printed in the next run's log. Pages is deployed only when the run's checkout holds `main`'s `publish/`, so a duplicate or queue-delayed wake never puts an older page back. The group, `cancel-in-progress: false`, the checkpoint windows, paid-attempt dedupe and continuity rules are unchanged.
- A `change` is bound to the comparison it names (E1): it cites only that comparison's `current_ref` and `prior_ref`, so admitted but unrelated evidence cannot back a claim about another measurement. Relationships and watch updates keep citing any admitted evidence. A comparison is `changed` only for a later entry whose value moved: a later entry at the same value is `no_new_observation`, one dated before the prior state is `not_comparable`, and `validate_state` re-derives the move from the record before it accepts a change.
- One configured analyst for every edition; identity, route, budget profile, and usage are recorded per run. No provider registry. A rejected generation is recorded as the call it was (`synthesis.calls`, route, requested model and, when a response arrived, usage and cost); a failure before any request is sent is not a call. A body cut off mid-read or an unparseable status line is a transport failure (no automatic paid retry), an error response whose body is cut off is classified by its status alone, and a 200 whose response, choice or message is not an object is a rejection with a bounded diagnostic, never a crash.
- The configured analyst carries one bounded fallback (`fallback_model`, Fable 5). A synthesis checkpoint attempts the primary and, only when OpenRouter reports it has no eligible endpoint (the explicit "no endpoints found" 404, a routing failure before any billing), makes exactly one fallback call; a bare or unrelated 404, transient, auth, malformed, and local-grounding failures never fall back, an environment override carries no fallback, and each run records the primary failure (sanitized, never the raw provider body), whether fallback occurred, and the model that served. OpenRouter's own `models` array is deliberately not used: a "no endpoints" 404 halts that chain rather than advancing it, and it would hide the primary failure and could bill twice.
- The configured primary analyst is Opus 5.5 (`anthropic/claude-opus-5.5`, owner ruling 2026-09-27) for both daily syntheses. The bounded fallback (Fable 5), the Anthropic-only provider pin, the rich and light profiles and budgets, the prompt, the narrative schema and the recorded provenance are unchanged, and a trading day still makes exactly two analyst calls. A workflow experiment runs the checkpoint it was dispatched with (`-f checkpoint=… -f experiment=true`); only a commissioning experiment resolves the market phase from the clock.
- Light editions receive a deterministically selected context and can cite only what they were shown; nothing is truncated to fit a budget.
- Rich interpretation is scarce: the premarket edition and the opening-structure update (open +30 minutes) are the day's only analyst calls. Open +1M, the hourly refreshes and the close are deterministic: they refresh the observed record under the last accepted interpretation, frozen as a hashed continuity record, and never rewrite it. The standalone rich CLOSE_1M edition is removed rather than fitted to a larger budget.
- Checkpoints are anchored to the exchange session, never to a Pacific wall clock: premarket at open −30 minutes, open +1 and +30 minutes, hourly refreshes at exchange-clock hours, the close at close +1 minute. The exchange calendar is the only authority; times are displayed in Pacific time and therefore move with New York's seasons (the opening-structure update reads 7:00 AM PT in New York daylight time and 8:00 AM PT in standard time now that British Columbia keeps UTC−7).
- A synthesis checkpoint is due only within its own short window (`schedule.TOLERANCE_MINUTES`, twenty minutes) so the wake that naturally follows it is its one attempt; the :31 UTC wake that exists for the other New York season lands thirty-one minutes late and resolves to SKIP, never a second paid attempt, whatever the first attempt's outcome. Deterministic refreshes and the close keep the forty-five-minute window.
- A watch's criteria keep the values their author saw: the rows a criterion quotes are frozen with the watch when it is created and travel with it; a later synthesis may reassess or replace the watch, a deterministic refresh may not, and newer market data never changes a carried threshold.
- The close snapshot hands the session off from deterministic state: closing snapshots from its own evidence, the carried assessment labeled with the checkpoint that interpreted it. A close without a same-session interpretation still hands off (no page); a close or refresh without observations from the session publishes nothing and leaves the last accepted page and bundle untouched.
- Every page states three clocks, each saying what it measures: **Prices**, the latest current equity print across the page's tables (else `prior close <date>`); **Analysis**, when the interpretation it shows was made and by which synthesis edition (`premarket`, `opening structure`); **Next**, the scheduler's next checkpoint in reader words (`price refresh`, `analysis update`, `close snapshot`, or the next session's `premarket analysis`). A synthesis whose prices and analysis read the same PT minute shows one `Prices & analysis` line. Prices is the visual anchor; the run's collection time stays in Technical details. The masthead carries the date; LIVE renders no status word, while SAMPLE, LIVE COMMISSIONING and LAST GOOD BRIEF stay loud with the edition named once. A carried page's "What changed" caption ends at its analysis ("… · through the 7:01 AM PT analysis"). Each row keeps its own observation clock or date; frozen prose cites the rows the analyst saw at their own clock, tables cite this run's rows.
- A page never claims freshness it no longer has: the Next line carries the next checkpoint's absolute time and its own PT words, and the page's inline script rewrites it to "Update due … has not published" once that time plus a fifteen-minute grace (`render.OVERDUE_GRACE`) has passed, on load, on becoming visible and every minute. The wording is neutral because the cause may be a failure or a legitimate no-publish. There is no server-side state, status value or network call, and without JavaScript the page is unchanged.
- The BLS release calendar identifies its robot and keeps one bounded official fallback (2026-10-02, the calendar half of issue #23). BLS blocks robots it cannot contact: its firewall refused every anonymous production request, the calendar file and the monthly pages alike, with HTTP 403, and served the same Python request once it carried `MarketBrief/0.1 (<owner address>)`. BLS requests, and only those, carry the owner's address from the `BLS_CONTACT` secret, which is never printed, persisted or rendered; without it the anonymous agent stays, a malformed one fails the source closed without echoing it, and nothing impersonates a browser. On BLS exactly two URL forms are requested, redirects included: the calendar file and the official monthly List View (`/schedule/<year>/<MM>_sched_list.htm`). The file comes first; when it cannot be fetched or read, the List View pages for the months of today and the next session are read, and each counts only if it proves it is that month's schedule: a heading names the month, its one release table has the Date, Time and Release columns and closes, every row is dated inside the month on a weekday that agrees, and the page states its times are Eastern. A row without a time is a holiday and times are New York time. Anything that means the table a reader sees is not the one parsed fails the page: a row or a withdrawal entry it cannot read, a schedule date outside the release table, a table end tag with no table open, a table left open, and a date being read on which BLS's own browser script withdraws a release (it did so for three February 2026 releases). A recovered calendar is AVAILABLE, its URL the page it read and its technical reason naming the months and why the file was not used; both failing is one visible UNAVAILABLE naming both. The paths share the file's thirty-second envelope, so a slow BLS cannot starve the sources after it. The file names its own zone `US-Eastern` (New York time); an unreadable zone fails the file, never the run. The event record and its `bls-event-<n>` form are unchanged; both paths number a run's releases by time and then release name, because the file and the List View order a shared time differently (Real Earnings before or after CPI) and a frozen reference must name the same release whichever path the next run read. A watch horizon `EVENT(<id>)` is a reference, not a numeric claim, so the validator's literal-digit rule no longer reads the digit in `bls-event-0` (it is still checked against the admitted events); before events reached production every such horizon would have been rejected after the paid call. The analyst reads each admitted release whole (`MODEL_EVENT_FIELDS`: id, title, scheduled time, session relation, source, status) and none of its collection plumbing; measurements keep their compact record and context items are unchanged. Release values (issue #23) stay out of this slice.
- BLS release actuals are read from BLS's fixed current-edition pages, only for the scheduled release, and shown on the page whatever the analyst does (2026-10-02, issue #23). The admitted calendar is the only trigger: when today's calendar lists the Employment Situation or the Consumer Price Index and its scheduled time has passed, the collector reads that family's one page (`news.release/empsit.nr0.htm`, `news.release/cpi.nr0.htm`, the only BLS pages besides the calendar, redirects included) with the identified request, once per run and within twenty seconds; it never fetches before the release or for another family, and never uses the Public Data API as the same-day source. A page is that release only if its embargo line's official time is the event's scheduled time and its reference month is the one the calendar names (the List View names it; the calendar file does not) and precedes the release; the previous edition still served after the release time is refused (`the page still shows the … release`), as is any other date or month. Two narrow readers, no general scraper: the CPI's four values come from Table A by its caption and its reference-month columns; the Employment Situation's page holds only prose, so its values come from BLS's standard sentences, every statement of a value must agree, the earnings change must agree with its cents and dollar level, each revision with its previous and revised estimates and the combined revision with their sum, and a value outside a plausible bound, a direction word outside a small vocabulary, a second heading or table, or a page that is not one news block fails the release closed. A rate or 12-month earnings statement whose own clause names another month refuses the release rather than stand in for the reference month. Revisions are read only when the paragraph reads cleanly; otherwise they are left out, the card says `Revisions · not read from the release`, and the source reads Degraded (available with a stated gap, not counted unavailable). A page that crashes a reader, or a malformed HTTP response, costs that release, never the run. Values are observation rows (`frequency: release`, units thousand jobs / percent / percent change, magnitude neutral) dated by the official release time, carrying the reference month and, for a revision, its month and estimates; normalization admits one only in the session that published it, so no earlier release ever reads as today's, and a prior-session row is a namespaced prior ref at most. The light analyst context keeps every release row whatever its ranking, and a release states its time and month once for its group. One deterministic card opens Macro & rates on the observed clock (a refresh shows the release it read, never the interpretation's), values as BLS prints them, uncoloured; an event whose release is admitted leaves What matters next, so a release is never both next and done. Every run reads the page afresh: a corrected page with the same identity replaces the values, and anything else fails closed for that run.
- Rates are Treasury's official daily par curve: fitted from indicative quotes near 3:30 PM ET and published once a business day, so every page shows the previous business day's curve and no intraday yield exists anywhere in the pipeline. The rates module leads Macro & rates with a dated caption ("U.S. Treasury par curve · Thu, Sep 24 · official daily observation", never "close", never a clock time), the four tenors 2Y/5Y/10Y/30Y, the 2s10s and 5s30s spread lines, the named curve move, an inline chart of the observed tenors with the prior entry dashed, and notes; the analyst's paragraphs follow as the why. Freshness is judged against weekdays, not NYSE sessions, because the bond market keeps holidays the NYSE trades through: a curve older than the previous weekday but at most five calendar days old reads "latest official daily observation"; older than that it is stale and shows its levels, date and a quiet note only, and its daily tenor and spread changes are not current evidence either (E1): `curve.stale_movement` withholds them from the authority filter (so from the analyst and the validator) and from the deterministic comparisons, while the dated levels stay citable and every row stays in the evidence record. The analyst frames the backdrop with it and never presents it as the cause of, reaction to or explanation for current-session prints; when the curve predates a release, the module and the analyst say so.
- The curve move is named by a pure deterministic classifier (`curve.py`, rule version `curve-move.v2`), never by the analyst: an ordered rule table over the integer 2Y and 10Y changes (twist, bear/bull steepener or flattener, slight steepening or flattening, parallel shift, broadly higher or lower with a mild tilt, little changed), with the 5s30s change able to make it a mixed move or add a long-end note. A parallel shift needs both legs at the threshold in one direction; when only the leading leg is there (Tue, Oct 13, 2026: 2Y −1, 10Y −3), v1 called it parallel and v2 calls it broadly lower with mild flattening, named by the sign of Δs. Its threshold is the configured bp SMALL magnitude (`config/magnitude.json`), read, never copied. The result is a typed, non-citable packet record (`packet["curve"]`) saved with the evidence and shown to the analyst read-only; the analyst names the move only with its label and cites the tenor and spread rows.
- Spreads are signed long minus short in whole basis points (`treasury-2s10s`, `treasury-5s30s` and their changes, derived from one entry's legs with `input_ids` and a formula version). Steepening means the signed spread rose, whatever the level's sign, so on an inverted curve steeper means less inverted; a spread level is a level (no plus sign, a minus only when inverted). Reader copy never says "today", "wider" or "narrower". `2s10s` and `5s30s` are bounded labels in analyst prose, exactly those forms.
- A move the reader should recognise before reading about it is shown as two measurements, not a story: What changed leads with what was observed (the verdict's reason), names the watch or relationship it judged as a labelled second line, and renders the cited measurement at its earliest and latest clock as `earlier → later` with a short verb and the window that names both clocks and phases; the arrow never claims the path between them, a premarket print never shares a window word with an intraday one, a pair the sentence already spells out is not repeated, and the `§` provenance opens under the comparison. An opened `§` drawer adds a small chart only when it shows what the rows cannot (the drawer cites the instrument's history, or at least three prints of one session): the last twenty regular closes and the cited prints as isolated dots, drawn only from history and rows the page already holds; two prints alone draw nothing, nothing is interpolated, no OHLC is drawn until real OHLC is held, and no new data is collected for it. Rates reach the opening only when the lead cites the curve: one small line after the take with the module's own tenors, spreads and label under the curve's date; the sentence, chart and detail live once, in Macro & rates.
- Rates are never coloured: yield and spread levels and their changes render in neutral ink, as `5.18%` and whole `bp`, everywhere they appear (tables, module, proof lines, ledger, prose placeholders). The sign carries direction and the curve move label carries meaning; rising yields are neither good nor bad.
- The metals table is captioned "Metals" inside Macro & rates, its caption led by its spread label and carrying its own clock (equity prints are current while the curve is prior-day; the prompt forbids tying one to the other); "Cross-asset structure" named more than the table holds, and a section of its own left the biggest cross-asset moves orphaned below the sectors (2026-09-28: GLD −3.21% and GDX −3.77% at the open, five screens down with no prose slot). The one macro paragraph may speak to gold and miners when they move the story; no Metals prose slot is added to the schema.
- A live run's evidence cutoff (`run.target_time`) is the moment collection finished, not the moment the run began (2026-10-11, after W41). Collection still runs on the run's start, which `collection_started_at` and "Generated UTC" keep. An IEX trade is bounded by the snapshot response that reported it, and that response time is the row's `retrieved_at` and the source's checked time. Before this, the snapshot was requested one to three seconds after the cutoff, and a ticker whose latest trade fell in that gap was dropped silently. That meant the busiest tickers, most often: on the 35 in-session pages of 2026-10-05 to 10-09, NVDA had no print on 25, AAPL on 22 and SPY on 20, against XLRE on 2. The close pages lost none, because after-hours trading a minute after 4:00 PM is thin. The cause is strongly supported by elimination: a missing ticker keeps its daily rows, and SPY always trades at mid-session. It is not yet confirmed against Alpaca's trade record. The future, stale and near-close rules are unchanged; only what they are measured against moved, by seconds. This amends the freshness rule in `docs/ARCHITECTURE.md`, which now separates run start, observation window, evidence cutoff and session cutoff.
- The regular-session close bounds what a current print can stand for (2026-10-12). An intraday trade stamped after the session's close is after-hours: it is refused as session evidence and named in Coverage limitations. It is never a closing or near-close print, a closing comparison, or the close handoff's snapshot. Before this, all nine scheduled close pages from Sep 25 to Oct 9 admitted two to four IEX trades from 4:00–4:02 PM (SPY on six of them) and counted them as session prints. Expect two to four fewer current prints on a close page, each named. A regular-session last trade at the close needs another source and is not in scope.
- No collector drop is silent (2026-10-12). Every symbol the IEX snapshot does not yield a current print for is named with its reason in the source's reason, and a partial snapshot reads Degraded, not Available. The reasons are: no prior-close history; no trade or prior close in the snapshot; no IEX trade yet this session; trade stamped after the snapshot response; not returned by the snapshot. A snapshot with no prints at all stays Unavailable. Rows the admission rules refuse (future, stale, after-hours) are still named one per row, as before.
- A current print's reader label is presentation, read from that row's own `observed_at` against the session's open and close: "Premarket", "Intraday" or "After-hours vs prior close", "Near-close vs prior close" for a PROVISIONAL print, and "Latest trade vs prior close" when the phase cannot be placed in this session or a table's prints span phases. One helper (`render.current_print_label`) supplies it to every path (markers, table proofs and captions, ledger). A frozen row keeps the phase it was observed in; nothing is labeled as the official close. The metric string (`premarket return`), evidence ID, identity key and comparisons are unchanged.
- Current availability is owned by this run's deterministic packet and source state: missing domains, coverage limitations, the Sources drawer and the evidence rows. The analyst's `banner.limitation` is point-in-time interpretation; it renders, with its marker, only on the synthesis edition that wrote it and is withheld, never edited, on carried editions.
- Reader surfaces use reader words; internal contract vocabulary (metric strings, statuses, checkpoint names, source reasons) stays valid in Technical details and the saved artifacts. The coverage list says `not collected` where the packet says `not automated`, and names market sections an edition could not fill as "Not in this edition"; optional Cuttingboard absence is not an editorial omission, and Technical details state its status and reason.
